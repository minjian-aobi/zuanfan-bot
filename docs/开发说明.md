# 开发说明

面向改代码的人。使用方法见根目录 [README](../README.md)。

技术栈：Python + ADB + OpenCV 模板匹配，驱动 MuMu 模拟器 12。OCR（pytesseract + Tesseract）只用来读两个数字：关注人数和晶钻数，不读聊天内容。

基准分辨率 960x540、220 dpi，ADB 地址 `127.0.0.1:16384`。所有坐标和模板都是在这个分辨率下标定的，换分辨率要重裁所有模板、重测所有坐标。

## 目录结构

```
start.bat            开控制面板
start_full.bat       一键全流程：关注列表 → 世界频道，无面板
requirements.txt
core/                脚本主体
tools/               调试与标定工具
once/                只需运行一次的：环境安装、防休眠等
templates/           模板图，与分辨率绑定
logs/                运行日志（自动生成）
shots/               截图与调试图（自动生成）
```

| 文件 | 作用 |
| --- | --- |
| `core/core.py` | 标定值、adb、模板匹配、去重、日志、单步动作、重启游戏 |
| `core/zuanfan_bot.py` | 世界频道：一轮的编排与主循环 |
| `core/follow_list.py` | 关注列表巡回、每日清理、料理排序 |
| `core/diamonds.py` | 晶钻 OCR、`Tracker` 记账、当日上限 |
| `core/enter_wait.py` | 加载页判定、进门撒花、进门后扫三星 |
| `core/avoid.py` | 点击落点避让：常驻 UI 控件和虚拟摇杆 |
| `core/modes.py` | 两档模式的纯逻辑与 `Settings` |
| `core/panel.py` | tkinter 控制面板 |
| `core/user.py` | 账号与每个账号的设置（存在 `logs/user.json`） |

`core/` 里的模块互相直接 import，从仓库根目录运行：`python core\panel.py`。`tools/` 里的脚本会自己把 `core/` 加进搜索路径并切到根目录，从哪运行都行。

拆成多个文件的原因：单文件过大时整份上传给 AI 会被默默截断，截断后语法上还能 import，很难当场发现。

## 命令行入口

```
python core\panel.py                                  控制面板（start.bat 就是开它）
python core\zuanfan_bot.py [--mode 1|2]               只跑世界频道，默认第 2 档
python core\zuanfan_bot.py --once                     只跑一轮
python core\zuanfan_bot.py --no-diamonds              关掉晶钻计数
python core\follow_list.py [--total N] [--target N] [--no-world]
                                                      关注列表巡回，没吃够转世界频道
```

公共参数：`--debug` 打印每次匹配的分数与坐标，`--quiet` 关掉过程提示。

## 世界频道流程

1. `ensure_world`：确保在世界频道 1。不在就点开公屏再切频道；点不开时先点撒花按钮或 `WORLD_CLOSE_PT` 清掉遮挡
2. 在 `CHAT_ROI` 里轮询钻饭字样。频道开着满 `TIMEOUT_TARGET`（30 秒）还没有就 `refresh_world` 换一批消息
3. 头像哈希去重
4. 按档位决定要不要吃、要不要先关注（判定逻辑在 `modes.py`）
5. 点头像，在 `VISIT_ROI` 里等拜访按钮，按档位读关注／取关按钮
6. 点拜访，交给 `enter_wait.enter_home`：先等加载页出现再等它消失，进门后扫三星，中途看到撒花按钮就点掉
7. 三星落点过一遍 `avoid.dodge` 再点，然后 `catch_all_bugs` 连抓
8. 吃到了就趁还在别人家读一次晶钻数，然后回第 1 步

硬规矩：任何「找到目标但直接 return」的分支必须自己调一次 `refresh_world`，否则会盯着同一批消息空转。`dup` 分支曾这样空转 3600 多轮。

### 两档模式

| 档 | 名称 | 行为 |
| --- | --- | --- |
| 1 | 无限制 | 钻饭同一行有粉丝字样就整轮跳过，记 `skip_fan` |
| 2 | 全部关注查重 | 每家都点关注，资料卡上是取关按钮就说明来过，记 `visited`。默认档 |

第 2 档的局限：对方的隐私设置可能让关注点不上，按钮永远不变成取关，这家会被当成没来过。所以它只能省时间，不能当可靠的去重。

## 关注列表流程

1. 依次点 `OPEN_PTS` 打开好友页并切到关注列表，用 `anchor_friends`、`anchor_follow` 确认到位
2. 每日清理：当天第一次运行时，取关列表里有 `mark_visit` 但旁边没有 `mark_food` 的人，最多 `PURGE_MAX`（100）个，做完写 `purge_<游戏日>_<账号>.flag`。必须在排序之前做
3. 料理排序：在 `ORDER_ROI` 里比较 `correctorder` 与 `wrongorder`，差值超过 `SORT_MARGIN` 才判定，排错了就点过来
4. 关注总数由 OCR 读 `x/400`，读到多少就处理多少家；读不出就问人，也可以用 `--total` 指定
5. 逐个处理：拜访 `VISIT_PT`、取关 `UNFOLLOW_PT`、下一个 `NEXT_PT`，点不动时交替点 `NEXT_ALT_PT`
   - 没有拜访权限：右下角 `RESTART_PTS` 两下回家 → 取关 → 下一个
   - 进门没吃到：取关
   - 吃到了：保留关注，跳下一个
   - 在派对里（看到 `xiayijia`「下一家」按钮）：右下角点不动，改点左上角 `HOME_PT` 回家
6. 每处理 `HOME_EVERY`（10）个人回一次自己家再继续
7. 吃满 `EAT_TARGET`（默认 999，等于不限）口或晶钻到上限就收工，否则带着已吃口数和晶钻计数器交给世界频道

## 晶钻计数

`diamonds.py` 在 `ICON_ROI` 里找 `diamonds` 模板，以图标中心为基准裁出右侧数字区（`NUM_W` 84 x `NUM_H` 20，左边裁掉 `NUM_SKIP` 防止混进半个图标），再交给 Tesseract。`TESSERACT_DIRS` 里列了常见安装路径，PATH 里找不到时逐个试。

- 晶钻数只在主界面和家园里显示，打开公屏或关注列表就被挡住，所以开工读数要抢在开列表之前，饭后读数要抢在回世界频道之前
- 每次读数和上一次比，超出 0 到 `JUMP_MAX`（20）就当 OCR 读错丢掉，不更新计数
- 同一个游戏日内重开脚本，起点从基线文件或当天晶钻日志恢复，不会重置 100 颗上限
- 开工读不出数时通过 `ASK` 钩子问人：面板弹窗，命令行在控制台输入
- 比起点多出 `DAILY_LIMIT` 颗就回家，面板上弹窗问继续还是收工

## 模板

`templates/` 里 28 张，全部在 960x540 下裁的。

| 文件 | 内容 |
| --- | --- |
| `zuanfan` `zuanfan_blue` `zuanfan_bluewhite` `zuanfan_whiteblue` `zuanfan_pink` `zuanfan_fox` | 聊天里的钻饭两字，一种气泡皮肤一张 |
| `fensi` `fensi_pink` | 粉丝字样 |
| `anchor_world` | 世界频道锚点，不分频道 |
| `anchor_world1` | 带「1」的锚点，判定是否在 1 号频道 |
| `anchor_friends` | 好友页标题 |
| `anchor_follow` | 关注列表里的小耶 NPC，判定已在关注列表 |
| `btn_visit` | 资料卡上的拜访按钮 |
| `btn_follow` `btn_unfollow` | 关注与取关按钮 |
| `btn_flower` | 派对界面的撒花按钮 |
| `xiayijia` | 派对里的「下一家」按钮，判定在不在派对 |
| `correctorder` `wrongorder` | 关注列表料理排序的正确／错误状态 |
| `mark_visit` `mark_food` | 关注列表条目上的可拜访／有饭标记 |
| `three_stars` `three_stars_b` `three_stars_l` `three_stars_r` | 三星气泡及变体 |
| `loading_dark` `loading_white` | 两种加载页 |
| `diamonds` | 顶部的晶钻图标 |

变体机制：`variants(prefix)` 会把 `prefix.png` 和 `prefix_*.png` 全试一遍，`find_any` 取最高分。所以带下划线的名字会被当成变体：1 号频道锚点必须叫 `anchor_world1`，不能叫 `anchor_world_1`。`btn_unfollow` 不以 `btn_follow_` 开头，所以和 `btn_follow` 是两个独立目标。

匹配模式：`COLOR_TPLS` 里的走彩色（`three_stars`，`enter_wait` 导入时追加 `loading`），其余转灰度。缺模板时调用方接住 `FileNotFoundError`，退回原来的流程，不报错。

## 阈值

| 名称 | 值 | 说明 |
| --- | --- | --- |
| `TH_DEFAULT` | 0.85 | 钻饭、锚点、拜访、撒花、粉丝、关注、取关 |
| `TH_WORLD1` | 0.92 | 1 号频道锚点。误判「已在 1 号」是硬伤，宁高不宁低 |
| `TH_STARS` | 0.80 | 三星气泡半透明，底下的家具每家不同。漏吃多了就降回 0.70 |
| `TH_LOADING` | 0.85 | 加载页，定义在 `enter_wait.py` |
| `TH_VISIT` | 0.80 | 关注列表可拜访标记，定义在 `follow_list.py` |
| `TH_FOOD` | 0.75 | 关注列表有饭标记，定义在 `follow_list.py` |

分数怎么读：0.85 以上可靠；0.75 到 0.85 可用，可适当降阈值；0.60 到 0.75 说明模板带了太多背景，要重裁；0.60 以下是当前画面确实没有，或者分辨率不对。`matchTemplate` 不处理缩放和旋转，尺寸差 3% 以内可以容忍，差 10% 就失效。

## 返回码

世界频道每轮一个，写进 `run_*.csv` 的 `result` 列。

| 码 | 含义 |
| --- | --- |
| `ok` | 完整跑完一轮 |
| `ok_fan` | 同上，进门前点了关注 |
| `no_world` | 找不到世界频道，多半是掉线 |
| `no_target` | 当屏没有钻饭 |
| `dup` | 头像最近拜访过 |
| `skip_fan` | 第 1 档主动跳过粉丝 |
| `visited` | 第 2 档看到取关按钮，判定来过 |
| `no_card` | 资料卡没出现，头像坐标可能偏了 |
| `no_stars` | 进门后没找到三星 |
| `error` | 这一轮抛了异常，主循环兜住继续 |
| `restart` | 卡住太久，重启了一次游戏 |

抓虫的退出原因写在 `exit` 列，只有 `clean` 算吃到：`clean` 三星和撒花按钮都不在了；`max` 抓满 `STARS_MAX` 次还看得见三星；`back` 中途被弹回世界频道；`blocked` 撒花界面点不掉。

## 日志

所有按天命名的文件都按**游戏日**算：凌晨 5 点（`GAME_DAY_RESET_HOUR`）之前算前一天。每类文件只保留最近 `LOG_KEEP`（3）个。

| 文件 | 内容 |
| --- | --- |
| `logs/run_<游戏日>.csv` | 世界频道每轮一行：`time` `result` `skin` `fan` `followed` `taps` `exit` `ate` `world_secs` `home_secs` `mode` |
| `logs/diamonds_<游戏日>_<账号>.csv` | 每吃到一口一行：`time` `source` `eaten` `diamonds` `gained` `delta` `ok`，用来核对「吃到」判定的准确率 |
| `logs/diamonds_start_<游戏日>_<账号>.txt` | 当天第一次读到的晶钻数，重开脚本时用来恢复起点 |
| `logs/purge_<游戏日>_<账号>.flag` | 当天已清理过关注列表 |
| `logs/user.json` | 账号列表与每个账号的设置 |

csv 用 `utf-8-sig` 编码，Excel 双击打开不乱码。Excel 开着文件时会锁住它，此时脚本改写同目录的 `_alt` 文件，关掉 Excel 后手动合并。

## 自愈

连续 5 轮 `no_world` 报警，并把当时画面存到 `shots/stuck_*.png`。连续 60 秒（`STUCK_GAME_RESTART`）没有一轮正常结果，就 force-stop 游戏重开，点两下进入，等加载页过去，再点开公屏切回 1 号频道；连续重启失败 3 次后不再重试。关注列表那边是同样的 60 秒和 3 次。

模拟器本身卡住、adb 发不出命令时这套没用，得在外面重启模拟器。

## 调试工具（`tools/`）

```
python tools\grab.py world                     截图存为 shots/shot_world.png
python tools\peek.py shot_world.png 2          标定坐标、框选裁模板，2 倍显示
python tools\check.py                          测所有模板，截当前屏幕
python tools\check.py --shot blue2 zuanfan     只测钻饭及其变体，截图另存为 shot_blue2
python tools\check.py --img shot_blue.png      拿现成图片测，不连模拟器
python tools\probe_loading.py                  采样加载页分数
python tools\probe_purge.py shot.png           在截图上测「没饭标记」识别
python tools\test_diamonds.py [shot.png] [N]   晶钻 OCR 测试
python tools\test_modes.py                     档位逻辑测试
python tools\t_avoid.py                        落点避让测试
```

只给文件名时先在 `shots/` 里找。

`peek.py`：左键单击打印坐标与比例，拖拽打印矩形与 ROI 四元组，`s` 存模板，`r` 清矩形，`q` 退出。显示的是放大图，坐标与模板都取自原图像素，所以裁模板只用这个工具，不要用画图。

`check.py` 的搜索范围与真正跑的时候一致：`zuanfan`、`fensi` 限在 `CHAT_ROI`，`btn_visit` 限在 `VISIT_ROI`，两个世界频道锚点限在 `ANCHOR_ROI`。

## 已知局限

- 分不清「发钻饭」和「求钻饭」的消息，误识别的代价是白跑一轮
- 去重基于头像哈希，头像相同的不同玩家会被当成同一个人
- 不会在家园里平移视角找三星，三星不在当屏就放弃这一家
- 三星阈值降到 0.70 时可能被背景撞出假峰，靠 `STARS_MAX` 次数上限兜住
- 只支持单开
